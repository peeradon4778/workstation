# SOLUTIONS — แผนที่โซลูชัน (หลังร้าน)

> **แนวคิดของคุณถูก:** แยก **Front end (หน้าร้าน)** กับ **Backend (ของที่ขาย)** เป็น 2 เรื่อง
> **Front end** = หน้างาน Fastwork ที่ลูกค้าเห็น
> **Backend** = สิ่งที่คุณทำจริง · library · กระบวนการ · เมนูโซลูชัน

---

## 1. 🏪 Front end vs Backend

| | Front end (หน้าร้าน) | Backend (หลังร้าน) |
| --- | --- | --- |
| **คืออะไร** | หน้างานบน Fastwork | สิ่งที่คุณทำจริง |
| **ใครเห็น** | ลูกค้า | คุณคนเดียว |
| **มีอะไร** | ชื่องาน · รูป · คำอธิบาย · แพ็กเกจ · พอร์ต | เมนูโซลูชัน · library · กระบวนการ · ราคาต้นทุน |
| **เปลี่ยนเมื่อไหร่** | เมื่ออยากได้ลูกค้าแบบอื่น | ทุกครั้งที่ทำงานเสร็จ (library โต) |
| **ความสัมพันธ์** | **แสดงเฉพาะ "ผลลัพธ์" ที่ลูกค้าสนใจ** | **เก็บ "วิธีทำ" ที่ลูกค้าไม่ต้องรู้** |

> **ห้ามเอา Backend ไปโชว์ที่ Front end**
> ลูกค้าไม่สนใจว่าใช้ extension อะไร เขาสนใจว่า **"จะได้อะไร ใช้ได้จริงไหม"**

## 3. 🧱 Backend: แผนที่โซลูชัน

### 3.1 🍱 เมนูโซลูชัน (ตายตัว — ลูกค้าเลือกชุด)

> **หลักการ:** เมนู **ตายตัว** · แต่ **ชุดที่ลูกค้าเลือก = custom**

| # | โซลูชัน | ทำอะไร | ราคาเดี่ยว |
| --- | --- | --- | --- |
| **S1** | **Setup & Onboarding** | ทำให้ harness ทำงานกับโปรเจกต์คุณ | ฿1,500 |
| **S2** | **Prompt Templates** | คำสั่งสำเร็จรูป 3–8 อัน สำหรับงานประจำ | ฿900 |
| **S3** | **Skill / Extension** | ทำให้คำสั่งเดียวทำงานซ้ำได้เอง | **฿700/อัน** |
| **S4** | **Context & Model Tuning** | ลด token + ทำให้ตอบตรงขึ้น | ฿1,200 |
| **S5** | **Team Packaging** | แพ็กให้ทีมติดตั้งใช้เหมือนกัน (git) | ฿3,500 |
| **S6** | **MCP Server** | ต่อ AI เข้ากับ API/ข้อมูลของคุณ | ฿3,500/อัน |
| **S7** | **Cost Audit** | วัดและลดค่า token · รายงานเป็นตัวเลข | ฿2,500 |
| **S8** | **Team Training** | อบรมทีมใช้ให้ตรงกัน | ฿3,500/ชม. |

**→ ลูกค้าเลือกจาก 8 อย่างนี้** — คุณรู้ล่วงหน้าว่าต้องทำอะไร และประเมินเวลาได้

### 3.2 🔑 แพ็กเกจ = "ชุดสำเร็จรูป" ของเมนู

| แพ็ก | ประกอบจาก | มูลค่า à la carte | ราคาแพ็ก | ประหยัด |
| --- | --- | --- | --- | --- |
| **ขั้น 1** | S1 | ฿1,500 | **฿1,500** | — |
| **ขั้น 2** | S1 + S2 + S3×3 + S4 | ~฿5,400 | **฿4,500** | 17% |
| **ขั้น 3** | S1 + S2 + S3×5 + S4 + S6 | ~฿9,900 | **฿9,900** | — |
| **ขั้น 4** | ทั้งหมด + S5 + S8 (2 ชม.) + ดูแล 3 เดือน | ~฿28,000 | **฿24,900** | 11% |

> **นี่คือคำตอบของคำถาม "โซลูชันตายตัวมีอะไรบ้าง"**
> **ตายตัว = เมนู 8 อย่าง · custom = ชุดที่ลูกค้าเลือก**

### 3.3 อะไรตายตัว / อะไรปรับตามบรีฟ

| ตายตัว 100% | ปรับตามบรีฟ |
| --- | --- |
| รายการในเมนู (8 อย่าง) | **ลูกค้าเลือกกี่อย่าง อะไรบ้าง** |
| กระบวนการ (ปรึกษา → บรีฟ → ตั้งค่า → อนุมัติ → ส่ง) | workflow ที่ต้องตั้งค่า |
| รูปแบบสิ่งที่ส่งมอบ (ไฟล์ · เอกสาร · วิดีโอ) | **เนื้อหา**ใน skill / template นั้น |
| ราคาต่อรายการ | ส่วนลดตอนรวมเป็นแพ็ก |
| ระยะเวลา + จำนวนแก้ | จำนวนรอบจริงที่ใช้ |
| สิ่งที่ไม่รวม | — |

### 3.4 📚 Library (Backend ที่โตขึ้นทุกงาน)

```text
library/
├── skills/            ← skill ที่ทำแล้ว ใช้ซ้ำได้
├── prompt-templates/  ← template ที่พิสูจน์แล้ว
├── configs/           ← ตั้ง context/model ที่ใช้ได้ทั่วไป
├── docs/              ← เอกสารที่เปลี่ยนแค่ชื่อลูกค้า
└── mcps/              ← MCP server ที่ทำแล้ว
```

**เป้าหมาย:** งานที่ 5 ต้องประกอบเสร็จใน 2 ชั่วโมงจากของใน library

## 4. 💭 "บริการแบบปรับตามความต้องการ" — ดีไหม

### ✅ ดี — เพราะ

| เหตุผล | หลักฐาน |
| --- | --- |
| ตรงกับที่ตลาดขอ | บรีฟใน jobboard เป็นโจทย์เฉพาะทุกอัน (import จากจีน · AI ตรวจงาน · ที่ปรึกษา 1 ชม.) |
| มูลค่าสูงกว่า | ลูกค้าจ่ายเพื่อ "ของที่ใช่กับเขา" ไม่ใช่ของสำเร็จรูป |
| คู่แข่งเลียนแบบยาก | คู่แข่งที่ขายแพ็กแข็งๆ ทำไม่ได้ |
| ตรงกับ "ทำไมเลือกผม" | *"ไม่ใช่ template สำเร็จรูป"* ← ข้อความของคู่แข่งที่ขายได้ 85 ครั้ง |

### 🔴 แต่ต้องมีกรอบ ไม่งั้นพัง 4 อย่าง

| ความเสี่ยง | ถ้าไม่มีกรอบ | แก้ด้วย |
| --- | --- | --- |
| **ขอบเขตบานปลาย** | ลูกค้าเพิ่มไม่หยุด | **เมนู 8 อย่าง + จำนวนตายตัว** |
| **ประเมินเวลาไม่ได้** | รับงานแล้วขาดทุน | ทุกอย่างในเมนูมีราคาและเวลาที่รู้แล้ว |
| **library ไม่โต** | ทุกงานเริ่มจาก 0 | ทุกงานต้องเหลือของเข้า library |
| **ต่อรองราคายาก** | ไม่มีหลัก | **มีราคาต่อรายการ = อ้างอิงได้** |

> ### 🎯 สูตรที่ถูก
> **"เลือกได้ตามใจ แต่เลือกจากเมนูที่ผมกำหนด"**
> ลูกค้ารู้สึกว่าออกแบบให้เขา · คุณรู้ว่าต้องทำอะไร

## 5. 🪝 Front end: 6 คำถามที่ลูกค้าถามในใจ + คำตอบที่ต้องแสดง

> **นี่คือคำตอบของ "ควรแสดง solution and answer อะไร"**
> ลูกค้ากดเข้ามาดู → เขาถาม 6 ข้อนี้ในใจ → **ถ้าไม่ตอบ เขาออกไป**

| # | คำถามในใจลูกค้า | ต้องแสดงอะไร | อยู่ในไฟล์ |
| --- | --- | --- | --- |
| **1** | *"คุณทำอะไรได้บ้าง"* | **บล็อก "สิ่งที่ผมทำ"** 5 ข้อ + ตัวอย่าง 3–5 ข้อ | LISTING-1 §3 |
| **2** | *"ผมจะได้อะไร"* | **บล็อก "คุณจะได้"** ระบุเป็น **จำนวนชิ้นชัดเจน** | LISTING-1 §3 |
| **3** | *"ใช้เวลากี่วัน"* | **ระยะเวลาต่อแพ็ก** + จำนวนครั้งที่แก้ | LISTING-1 §5 |
| **4** | *"ผมต้องเตรียมอะไร"* | **Worksteps** — บอกว่าขอข้อมูลอะไรจากเขา | LISTING-1 §4 |
| **5** | ⭐ *"ถ้าได้ของไม่ตรงที่คิดล่ะ"* | **"ส่งให้ดูก่อนอนุมัติ — ไม่ตรงแก้ให้"** + **"ไม่รวม"** เขียนชัด | LISTING-1 §3, §7 |
| **6** | *"ทำไมต้องคุณ ไม่ใช่คนอื่น"* | **"ทำไมเลือกผม"** — บอกว่า **ไม่ใช่อะไร** | LISTING-1 §3 |

### ⭐ คำถามที่ 5 สำคัญที่สุด

**นี่คือสิ่งที่รีวิวจริงบอก:**
> ลูกค้าเขียนชมว่า *"ได้ตามที่หวังเอาไว้"* · *"ตามบรีฟทุกอย่าง"* · *"ได้สิ่งที่ต้องการครบ"* — **3 รีวิวพูดเรื่องเดียวกัน**
> **= ความกลัวอันดับ 1 ของเขาคือ "จ่ายแล้วได้ของไม่ตรง"**

**→ เพราะงั้นประโยคที่ต้องมี:** *"ส่งให้ดูก่อนอนุมัติ ไม่ตรงแก้ให้"*
**และ:** *"ระบุชัดว่าได้อะไร กี่ชิ้น กี่วัน — ไม่มาก ไม่น้อย"*
